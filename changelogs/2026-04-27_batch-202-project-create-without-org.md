# Batch 202: Відновлення створення проєкту без організації

## Як було
- Модалка створення проєкту блокувала submit, якщо користувач не мав жодної організації (`organizations.length === 0`).
- Вставка в `projects` завжди примусово передавала `org_id`, що не підходило для сценарію personal workspace.
- У `ProjectModal` використовувався `toast` без локального оголошення хука в цьому компоненті.
- Текст у полі Organization показував технічний fallback `Loading organization...`, що вводило в оману.

## Що зроблено
- У `ProjectModal` додано локальний `const toast = useToast();`.
- У submit-guard прибрано блокування за відсутності організації: залишено блокування тільки коли відсутній `user`.
- Підготовлено умовний payload для insert у `projects`: `org_id` додається тільки якщо `organizations[0]?.id` існує.
- Змінено fallback-текст Organization на `Personal workspace (no organization)`.
- Виконано таргетований тест: `src/pages/__tests__/Projects.test.tsx` (pass: 10/10).

## Що покращило/виправило/додало
- Виправлено blocker: користувач може створити новий проєкт навіть без прив'язаної організації.
- Зменшено ризик runtime-помилки в `ProjectModal` через відсутній локальний `toast`.
- Покращено UX: у модалці явно показано сценарій personal workspace замість «вічного loading».
- Збережено низький ризик змін: фікс локалізований в одному UI-файлі.
