# Batch 30: TS/JS Duplicate Cleanup And Guard

## Як було
- У кодовій базі співіснували пари `*.ts`/`*.tsx` і `*.js` з однаковим шляхом.
- Це створювало ризик неправильного module resolution у тестах/рантаймі та повторних регресій.
- Якість проходила нестабільно залежно від того, який файл резолвився першим.

## Що зроблено
- Видалено всі `*.js` дублікати в `src/` та `supabase/functions/`, де існує sibling `*.ts` або `*.tsx`.
- Додано захисний скрипт перевірки:
  - `scripts/check-no-ts-js-duplicates.cjs`
  - сканує `src` і `supabase/functions` та падає, якщо знаходить `*.js` поруч із `*.ts`/`*.tsx`.
- Оновлено npm-скрипти в `package.json`:
  - додано `check:no-js-duplicates`
  - включено цей крок на початок `quality:check`.
- Проведено перевірку:
  - `npm run check:no-js-duplicates` — PASS
  - `npm run quality:check` — PASS (lint + typecheck + tests + build)

## Що покращило / виправило / додало
- Усунуто клас помилок, пов’язаних із неочікуваним пріоритетом JS над TS.
- Зменшено ризик прихованих регресій у Vitest і локальному дев-рантаймі.
- Додано автоматичний превентивний контроль у quality gate, який блокує повторне потрапляння таких артефактів у гілку.
