# 2026-05-04 — Деплой агента на VPS + фікс case-insensitive роутингу сканерів

## Як було
- Актуальний фікс у репозиторії (`157afbf`) для нормалізації назви сканера (`toLowerCase`) ще не був задеплоєний на VPS.
- На VPS агент працював окремим Node.js процесом через `sentinel-agent.service`, а не через Docker-контейнер.
- Сканери з UI, що приходили як `Tfsec`/`Amass`/`Prowler`, могли некоректно потрапляти у fallback-гілку.

## Що зроблено
- Перевірено фактичний runtime на VPS (`192.168.10.80`): знайдено робочу директорію `/opt/sentinel-agent/` та repo-директорію `/opt/sentinel-agent-repo/sentinel-agent/`.
- Підтягнуто `main` у repo-директорії та виконано збірку (з `devDependencies`, бо `tsc` відсутній при `--omit=dev`).
- Оновлений `dist/index.js` скопійовано у runtime-директорію `/opt/sentinel-agent/dist/index.js`.
- Перезапущено процес агента (через kill/pkill), підтверджено автопідіймання через `sentinel-agent.service`.
- Верифіковано доступність health endpoint: `http://192.168.10.80:9090/health`.

## Що покращило/виправило/додало
- Фікс case-insensitive роутингу сканерів реально застосовано у прод-рантаймі агента на VPS.
- Зменшено ризик помилкового fallback на інший сканер через різний регістр назви з UI.
- Підтверджено працездатність сервісу після перезапуску (новий `startedAt`, живий `/health`, активний `sentinel-agent.service`).
