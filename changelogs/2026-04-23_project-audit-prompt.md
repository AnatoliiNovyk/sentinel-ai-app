# Зміни від 2026-04-23: Створення reusable prompt для аудиту

## Як було
- У репозиторії не було готового `.prompt.md` для повного аудиту проєкту.
- Не існувало стандартизованого шаблону, який в одному запуску генерує:
  - детальний звіт,
  - план виправлення багів,
  - список покращень та апдейтів.

## Що зроблено
- Створено workspace prompt: `.github/prompts/project-audit-remediation-roadmap.prompt.md`.
- Додано чітку роль, мету та формат результату (Markdown, українська мова).
- Зафіксовано обов'язкову структуру відповіді з 7 секцій:
  - Executive Summary,
  - повний технічний звіт,
  - план виправлення багів,
  - backlog покращень/апдейтів,
  - roadmap 30/60/90,
  - ризики та припущення,
  - top-10 action list.
- Додано правила доказовості (підтвердження через реальні артефакти репозиторію).
- Додано правила пріоритизації, effort-оцінки та критеріїв приймання.

## Що покращило/виправило/додало
- Додано повторно використовуваний інструмент для аудиту без ручного складання структури щоразу.
- Підвищено якість та відтворюваність звітів через обов'язкові докази й секцію Hypothesis/Needs Validation.
- Прискорено підготовку плану робіт після аудиту за рахунок вбудованої фази remediation і дорожньої карти.
- Зменшено ризик пропуску критичних елементів аудиту завдяки уніфікованому шаблону.
