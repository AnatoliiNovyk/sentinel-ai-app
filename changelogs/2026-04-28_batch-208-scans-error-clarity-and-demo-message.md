# Batch 208: Scans — ясність помилок і Demo-повідомлення

## Як було
- На сторінці сканів банер Demo Mode стверджував, що агент недоступний, навіть коли агент був онлайн, а вибраний скан був просто історичним MOCK.
- При провалі запуску скану UI часто показував `Failed to start scan: Unknown error`, що не давало зрозуміти причину.
- Можна було відправити запуск без валідного target і отримати непрозору сервісну помилку.

## Що зроблено
- У [src/pages/Scans.tsx](src/pages/Scans.tsx):
  - оновлено текст Demo-банера на нейтральний для історичного simulated-run;
  - додано pre-dispatch валідацію target (поле + fallback до project.target), з чітким повідомленням про помилку.
- У [src/api/scans.service.ts](src/api/scans.service.ts):
  - додано парсинг помилок `supabase.functions.invoke` (JSON/text із context);
  - замість сирої помилки тепер кидається `Error` з корисним повідомленням, яке і відображає UI.

## Що покращило/виправило/додало
- Усунено хибну інтерпретацію Demo банера як поточної недоступності агента.
- Користувач отримує змістовні причини провалу запуску скану замість `Unknown error`.
- Зменшено кількість невалідних dispatch-спроб завдяки ранній валідації target.
- Якість перевірено: lint і build проходять успішно.
